# Pump12 Layer 2 — TWAP、BurnNet 与 Anchor 执行清单

**目标：** 为每个 Pump12 官方池建立唯一可信的 TWAP、独立 BurnNet 七档回购网和 Anchor 状态机，完成 `pending → poke → position → harvest → burn` 闭环。

**约束：** 经济参数遵循 `docs/PUMP12_NETNET_BURNNET_SPEC_CN.md`；USDG 账本必须按 `poolId` 隔离；任何改变 Anchor 或部署回购资金的操作都必须依赖有效 TWAP；`harvest` 不依赖预言机。

## 1. NetNetHook TWAP

- [x] Listing 初始化首个观测点；swap 后更新累计 tick，开放 permissionless checkpoint。
- [x] 每池使用 32 个观测点的环形缓冲，最短 checkpoint 间隔 30 分钟。
- [x] TWAP 最短窗口 4 小时、最长窗口 8 小时、最新观测最多陈旧 1 小时。
- [x] 当前时间戳形成的 spot/观测不能参与本次 `poke`；同时间戳 swap 只更新后续累计使用的 tick。
- [x] 输出统一为 `USDG per whole Token` 的 WAD 价格，并支持要求全部观测形成于某时间点之后。

## 2. BurnNet 实例与 Pending 交接

- [x] 每个 Token 在 Listing 时创建唯一 BurnNet 实例并登记到 Hook。
- [x] Hook 只允许登记的 BurnNet 按比例提取自己的 `pendingUSDG` 与 eligible 子账。
- [x] 外部 `addPendingUSDG(poolId, amount)` 保持开放，但不计入 Distributor eligible reserve。
- [x] 每次提取满足 `pendingBefore = keeperPaid + activated + pendingAfter`，跨池余额不可互相挪用。

## 3. Anchor 与 poke 状态机

- [x] Listing 初始 Anchor 固定为曲线终点价，首次 `poke` 不早于 Listing 后 8 小时。
- [x] 正常更新为 `max(oldAnchor, min(TWAP, oldAnchor * 1.08))`。
- [x] TWAP 跌破当前最深档时触发向下重启：generation 加一、Anchor 下移、所有 mint 模块冻结 24 小时。
- [x] 重启后的解冻判断必须使用完全在重启后形成的有效 TWAP。
- [x] `poke` 领取 keeper 奖励、结算旧仓位、更新 Anchor、部署本轮 Pending 并保存 reserve snapshot。

## 4. 七档 v4 回购仓位

- [x] 价格档位固定为 Anchor 下方 5%、10%、15%、20%、30%、40%、50%，并完成两种币种排序的 tick 数学。
- [x] 首代资金按 L1/L2/L3 = 8%/12%/80% 分配；后续按 kappa3 规则决定补充优先级。
- [x] 使用仅含 USDG 的单边 maker 仓位；仓位 owner、salt、tick、principal 和 eligible 份额均可追踪。
- [x] 无法形成流动性的 rounding dust 留在该 BurnNet 的 liquid 余额，不得划给其他池或其他用途。

## 5. harvest 与销毁

- [x] `harvest` permissionless，只结算已经完全穿越的仓位，不要求 TWAP 有效。
- [x] 从 v4 取回 Token 后立即销毁，并更新累计 burn、层级未成交 USDG 和 eligible 消耗。
- [x] Token 提供仅销毁调用方自身余额的接口，不恢复任意外部 mint 权限。
- [x] 覆盖部分成交、完全成交、重复 harvest、重启前旧 generation 仓位和恶意调用者。

## 6. 验收

- [x] 单元测试覆盖环形缓冲、时间边界、同区块操纵隔离、两种币种排序和价格精度。
- [x] 单元测试覆盖 Anchor 单次最多上移 8%、向下重启、24 小时冻结重置和 Pending 守恒。
- [x] Robinhood fork 完成 fee → pending → poke → 穿档 → harvest → burn 的真实 PoolManager 闭环。
- [x] 定向测试、完整本地回归和合约 runtime size 检查全部通过；等待提交指令。
