# Pump12 Layer 1 — Curve、Listing POL 与 Hook Fee 执行清单

**目标：** 在不接入 BurnNet 七档仓位的前提下，完成一条 Token 从 USDG 内盘到 Robinhood canonical Uniswap v4 官方池交易的闭环。

**约束：** 经济参数完全继承 `docs/PUMP12_NETNET_BURNNET_SPEC_CN.md`；现有 V9 合约只读；每个子阶段先写失败测试，再写最小实现。

## 1. CurveMath 整数标定

- 固定按 Pump9 曲线形状等比例得到的 `bRaw`；用 Solady 实际整数运算反解并搜索 `aRaw`。
- `costRawUSDG(0, 750M)` 必须精确等于 `15_000e6`。
- 覆盖零数量、越过 750M cap、分段成本、WAD/raw6 舍入和边际价格。

## 2. Token12 与 Pump12 创建流程

- Token 初始化时一次性预铸 `750M + 250M`，内盘只转移预铸库存。
- 创建参数固定 `f`、`c`、创建者收款地址、Index ID、pTEAM holder；校验全部边界。
- 买入使用 exact-input USDG；最后一笔只使用 fill-to-cap 所需金额并退还其余 USDG。
- 卖出按曲线毛退款扣内盘 TagAI/创建者费用。
- 内盘费用采用拉取式账本，恶意收款合约不能阻塞交易。

## 3. PermanentLiquidityVault 与 Listing

- 离线标定 Token/USDG 实际排序、`sqrtPriceX96`、全域 ticks 和 liquidity delta。
- Vault 只允许 Pump12 初始化一次基础仓位，不暴露 decrease、collect、transfer 或任意 unlock 入口。
- Listing 原子关闭曲线、固定 `initialAnchor`、投入 `250M + 15,000 USDG`、注册 Hook/poolId，并记录 `listTime`。
- 本地 mock PoolManager 覆盖回滚原子性和基础 liquidity 永不下降。

## 4. NetNetHook 费用与 Pending 总账

- 只接受 Pump12 注册的官方池；按 PoolKey 动态识别 USDG 方向。
- 第一版只支持 exact-input；买入 `beforeSwap`、卖出 `afterSwap` 结算 Hook delta。
- TagAI/创建者使用可领取子账；BurnNet 份额进入指定 poolId 的 Pending 与 Eligible 子账。
- `addPendingUSDG` 余额差记账且永远 non-eligible；跨 poolId 状态隔离。
- 覆盖两种地址排序、三方守恒、恶意收款合约、错误 delta 权限和 exact-output 拒绝。

## 5. Robinhood fork 验收

- 在 chain ID `4663` 对 canonical USDG、PoolManager 重新检查地址、代码和 decimals。
- 完成 create → 买满内盘 → list → 官方池双向 exact-input swap。
- 验证基础 POL、Hook 分账、Pending、Token/USDG delta 和 mint 权限交接。

- 定向测试、完整本地回归和 RH fork 全部通过后，再勾选主计划 Task 1 并提交。
