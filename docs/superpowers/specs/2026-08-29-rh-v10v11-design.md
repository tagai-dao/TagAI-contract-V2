# RH V10 导入 + V11 发行栈设计

日期：2026-08-29  
基线分支：`rh`  
行为参考：`main`（BSC Pump V11 / ImportHelper V10 / Index Broker NFT）  
目标分支：`rh-v10v11`（从 `rh` 拉出）  
发布模型：三期顺序开发，**最后一次性部署**；旧 RH Pump 已发 Token 不迁移。

## 1. 目标

在 Robinhood 链上，让新发社区代币具备 main V11 的发行/费率/注入行为，让外部 ERC20 导入具备 main V10 后来补齐的登记与 Nutbox token fee 能力，并上线 Index Broker NFT。DEX、定价和已有 RH 基础设施保持 RH 模型。

## 2. 硬约束（全程有效）

1. 不把 Pancake Infinity Vault / `lockAcquired` / BSC 地址写进 RH 发行栈。
2. Token / Hook / Wrapper 继续使用 Uniswap v4 `unlockCallback` + `CurrencySettler`。
3. Pump 继续使用 `NutboxDeployConfig` 构造函数。
4. 曲线 `a = 1_624_898_729`，上市预算 `LISTING_ETH_BUDGET = 4.8 ETH`，tick / liquidity 用现有 RH 标定值。
5. `tickSpacing = 60` 保持不变。
6. 不覆盖 RH 的 NFT Mining / Basket Mining / ERC20Staking / ERC20Locking。
7. 不删除 `TagAISwapWrapper`，不替换为 BSC 的 `ImportedTokenSwapWrapper`。
8. ImportHelper 继续强制为导入者创建 IPShare；创建路径继续允许调用方传入 `calculator` 和 `distributionPolicy`。
9. Wrapper ETH 侧费率保持 RH 现默认（sellsman 1% + platform 1%），不改成 BSC 的 0.2%。
10. 不改 `deployments/56/*`。新地址写入 `deployments/4663/` 与 `deployments/46630/`。
11. 旧 RH Pump 克隆出的 Token 继续走旧实现；本次只影响新 Pump。

## 3. 与 main 对齐的行为

### 3.1 发行栈（V11 行为）

- `Pump.createToken` 在转 Community owner 之前调用 `adminSetDev(creator)`。
- 只有 Pump 捆绑预购走普通 `feeRatio`；公开第一笔买入也走 15 秒 anti-snipe。
- 15 秒窗口内禁止触发上市。
- 上市池 `PoolKey.fee = 3000`（0.3% 原生 LP Fee）。Hook 费率是另一条路径。
- Token 上市时快照 `listingHook`；之后换 Pump 默认 Hook 不影响旧池。
- 任何人可调 `collectFees()`：`liquidityDelta = 0`。ETH LP Fee 的 0.5% 给调用者，其余给 `Pump.getFeeReceiver()`；社区 Token LP Fee 给 `listingHook`。领取走 PoolManager `take`，Token 不暂存。
- Hook 上市后不再读 `Pump.feeRatio`。买入：ETH 侧 0.3% → IPShare，Token 输出 0.3% 留在 Hook。卖出：同一笔 ETH 毛额 0.3% → IPShare，0.3% → 平台。
- Nutbox 注入按 Hook 实际 Token 余额，去掉递减 `remaining`。注册时读该 Community 的 `rewardCalculator()`。
- `_antiSnipeInject` 在 `nutboxCommunity == address(0)`（premine 未绑社区）时回退到 IPShare `valueCapture`，不读 calculator；社区绑定后才用 `ICommunity(nutboxCommunity).rewardCalculator()`。

### 3.2 导入（V10 能力补齐，RH 形态）

- Helper 与 Wrapper 双向登记：token → `{community, deployer}`，同一 token 只能登记一次。
- 可传入已有 Community：校验 Factory、community token、calculator 后只登记不新建。
- 已登记 token 抽 Token 侧 Nutbox fee（默认 0.2%，可配），按 10 分钟注入绑定 Community。
- 提供 `quoteBuy` / `quoteSell`。
- V2 税币买卖、V3 买入按实际到账；V4 税币能力不超出 RH Wrapper 现状。
- 拒绝 `Pump.createdTokens(token) == true` 的地址，避免双 Community。

### 3.3 Index Broker NFT

- 从 main 迁 Factory / NFT / AMM / Renderer / Stonk 逻辑。
- 官方 Token AMM 激活使用 `INutboxRouter.UniswapV4Source`，从 Token 的 `listingHook`、`poolManager`、`LISTING_LP_FEE`、`TICK_SPACING`、`v4PoolId` 重建，不调用 Pancake `poolIdToPoolKey`。
- 指数回购与现货价走 RH 配置的 Uniswap V2/V3/V4 + `NutboxRouter`。Pancake Infinity 路径在 RH 部署中不启用。
- Factory 部署后默认未授权，Owner 交接和白名单放发布清单最后。

## 4. 明确不在范围内

- 迁移或升级已经部署的 RH Pump / Token / Hook。
- 把 BSC `ImportedTokenSwapWrapper` 或 BSC Hook 字节码直接部署到 RH。
- 改变 RH 上市 ETH 数量去对齐 BSC 的 ~19.17 BNB。
- 用 BSC `BSCNFTMiningRenderer` 替换 RH `NFTMiningRenderer`。

## 5. 三期与依赖

```text
第 1 期  Pump / Token / Hook
    ↓ 新 Token 暴露 listingHook、LISTING_LP_FEE、v4PoolId
第 2 期  ImportHelper / TagAISwapWrapper
    ↓ 外部 ERC20 有 Community + 可交易包装
第 3 期  NutboxRouter + Index Broker NFT
    ↓ 官方 Token AMM 依赖第 1 期上市池（fee=3000）
统一发布  新 Pump + Hook + Helper + Wrapper + Router + Index Broker
```

每一期结束必须：相关单元测试通过；RH 本地 Uniswap v4 测试通过；不部署主网。第 3 期结束后才做 fork 全链路与部署脚本终态。

- 先写失败测试，再改生产代码（TDD）。
- 行为断言对齐 main V11/V10 文档，调用接口保持 Uniswap v4。
- 回归：现有 `test/unit/Pump.t.sol`、`Token.t.sol`、`TagAISwapHook.t.sol`、`RHV4ListingLocal.t.sol`、`ImportHelper.t.sol`、`RHImportWrapper.t.sol`、NFT/Basket mining 测试不得无故删除。
- Fork 测试使用 `FOUNDRY_PROFILE=rh_fork`，不使用 BSC fork profile 作为 RH 发布门槛。
